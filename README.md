# Sharing Board

当前版本：`V1.6.0`

Sharing Board 是一个面向局域网的多设备加密传输工具，可在手机、电脑和平板之间发送文字与文件。文字、文件内容及发送者资料均在浏览器端加密；服务端负责房间路由、密文转发及必要的内存缓存，不参与解密。

## 主要功能

- 扫码连接：启动后展示邀请二维码，其他设备进入房间后自动打开传输界面
- 统一会话：文字与文件在同一个即时会话界面中发送
- 多设备互传：一台设备发送后，同一房间内的其他在线设备均可接收
- 设备识别：支持自定义昵称、图片头像、文字头像及颜色，并使用稳定短码区分同名设备
- 文件识别：根据文件类型展示照片、视频、文档或普通文件图标
- 浏览器端加密：使用 `PBKDF2-SHA256 + AES-GCM-256` 加密文字、文件及发送者资料
- 分片与续传：文件分片发送，支持临时断线后的自动重连与缺失分片补传
- 响应式界面：适配 PC、平板和移动端，并支持主题颜色与明暗模式
- 局域网 HTTPS：启动时自动检查并生成覆盖当前局域网地址的自签名证书

## 运行要求

- Windows 10/11 可使用 `Run.bat` 一键启动
- Python 3.10 或更高版本
- 设备位于允许相互访问的同一局域网
- 浏览器支持 WebSocket、Web Crypto API 和 Blob 下载
- Windows 防火墙允许 Python 或 TCP 端口 `8000` 的局域网访问

## Windows 快速启动

双击运行：

```bat
Run.bat
```

启动脚本会自动：

1. 检查 Python 和项目依赖
2. 检查并生成 `key.pem` / `cert.pem`
3. 选择可供其他设备访问的局域网 IPv4 地址
4. 生成随机房间号和访问密钥
5. 启动 HTTPS 服务并打开二维码首页

终端会显示本机访问地址、房间号和访问密钥：

```text
https://你的局域网IP:8000
```

首次访问自签名 HTTPS 地址时，浏览器可能显示安全提示。需要先在每台设备上确认继续访问，浏览器才能建立加密 WebSocket 连接。

## macOS / Linux 手动启动

```bash
python3 -m pip install -r requirements.txt
python3 gen_cert.py
python3 -m uvicorn main:app --host 0.0.0.0 --port 8000 \
  --ws-max-size 524288 \
  --ssl-keyfile key.pem --ssl-certfile cert.pem
```

启动后请使用终端显示或系统查询到的局域网 IP 访问，例如 `https://192.168.1.20:8000`。不要使用二维码中的 `localhost` 地址连接其他设备。

## 使用方式

### 连接其他设备

1. 在主设备打开启动页面并等待二维码就绪
2. 使用同一局域网内的手机、电脑或平板扫描二维码
3. 对方设备进入房间后，主设备自动展开传输界面
4. 展开后可通过右上角分享按钮再次查看二维码或复制邀请链接

### 发送文字与文件

- 在底部输入框输入或粘贴文字，按 `Enter` 或点击“发送”
- 点击文件夹图标选择一个或多个文件，文件会按照队列依次发送
- 自己发送的内容显示在右侧，其他设备发送的内容显示在左侧
- 接收文件后，点击文件类型图标下载到当前设备
- 文字气泡右下角提供一键复制按钮

### 设置设备资料

- 点击传输界面右上角的设备头像修改昵称和头像
- 未选择图片头像时，默认使用昵称首字作为文字头像
- 设备资料和偏好保存在当前浏览器，不会跨浏览器自动同步

## 文件传输边界

- 单文件大小上限为 `128 MB`
- 默认分片大小为 `256 KB`
- 服务端会再次校验文件总大小、分片大小、分片数量、索引和消息尺寸，不能通过修改前端绕过上限
- 多个文件按队列顺序发送，不会同时占用多条上传任务
- 接收端会在浏览器内存中收集解密后的分片，再合并为可下载文件；低内存手机处理接近上限的文件时可能失败
- 自动续传仅适用于原发送页面仍然打开、文件对象仍在且服务端进程未重启的临时网络中断
- 刷新或关闭发送页面、重新选择房间、重启服务后，不能继续原传输，需要重新选择文件
- 服务端不保存完整会话历史；新加入设备只会收到服务器内存中最近的加密文字和最近一次文件传输状态
- 无设备在线的房间在闲置 `30 分钟`后会自动清理；服务端总密文缓存上限为 `256 MB`
- 默认最多保留 `64` 个房间、`128` 个在线连接，每个房间最多 `16` 台设备
- 当前不适合超大文件、跨天传输、后台持久下载或长期文件存储

## 安全与隐私

- 房间密钥在浏览器端通过 `PBKDF2-SHA256` 派生，内容使用 `AES-GCM-256` 加密
- 邀请二维码在浏览器本地生成，不再把包含访问密钥的邀请链接提交给服务端
- 邀请链接使用 URL Fragment 保存房间号和访问密钥，正常页面请求不会把 Fragment 发送给服务器
- 服务端可以看到连接 IP、房间号、密文长度、文件总大小、分片数量和传输时间，但看不到文件名、文字内容、文件内容、昵称或头像明文
- 服务端会在内存中临时保存最近一条加密文字、最近一次文件的加密分片及续传状态；停止服务后这些内容会清空
- 邀请链接本身包含访问密钥，获得链接的人可以加入房间，请勿通过公开渠道分享
- 自签名证书用于加密局域网传输，但不等同于公共 CA 的身份验证
- WebSocket 连接会校验浏览器请求来源，页面响应包含内容安全策略、防嵌入和禁止 MIME 嗅探等安全响应头
- 本项目没有账户系统；任何获得完整邀请链接的人都可以加入对应房间
- 本项目适合可信局域网内的临时传输，不应作为高强度涉密系统或永久文件存储服务
- 不要配置公网端口转发、直接暴露到互联网，或将其当作面向不受信任用户的公共托管服务

发现安全问题时，请不要在公开 Issue 中披露利用细节，按照 [SECURITY.md](SECURITY.md) 中的流程报告。

## 常见问题

### 手机扫码后无法打开

- 确认手机和电脑位于同一 Wi-Fi 或可互访的局域网
- 避免使用启用了客户端隔离的访客网络
- 检查 Windows 防火墙是否允许 Python 或端口 `8000`
- 确认二维码地址是局域网 IP，而不是 `localhost`、`127.0.0.1`、VPN 或虚拟网卡地址

### 页面能打开但无法互传

- 先在该设备上接受自签名证书安全提示，再重新进入房间
- 确认所有设备使用同一个房间邀请链接
- 保持发送页面位于前台，避免手机系统冻结浏览器

### 大文件发送中断

- 确认接收设备有足够可用内存和存储空间
- 传输期间避免锁屏、切换网络或关闭浏览器页面
- 自动重连失败时重新选择原文件发送

## 技术栈

- 后端：Python、FastAPI、Uvicorn、WebSocket
- 前端：HTML、CSS、Vanilla JavaScript、Web Crypto API
- 二维码：浏览器端 `qrcode-generator 1.4.4`（MIT）
- HTTPS 证书：Python `cryptography`

```bash
python -m pip install -r requirements-dev.txt
python -m unittest discover -s tests
```

```bash
node --check static/script.js
```

```bash

python -m bandit -r main.py gen_cert.py launch_config.py -q
detect-secrets scan
```
